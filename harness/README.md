# Tests

Each language tests itself on the shared data: [`spec/cases/`](../spec/cases/README.md), [`spec/limits.json`](../spec/limits.json) and [`spec/cli.json`](../spec/cli.json). The tests take a short run by default, and `FULL_CASES=1` runs every known term but the counts copied from the OEIS, which the solver of their file has not counted.

A short run stops `domino-rectangle-bigint` and `domicule-rectangle-bigint` at the 16 × 16 square and `any-lattice-cylinder-torus-bigint` at the 8 × 8 torus. `any-lattice-cylinder-torus-modular`, `any-lattice-rectangle-modular`, `any-lattice-cylinder-torus-polynomial-modular`, `any-lattice-rectangle-polynomial-modular`, `domicule-rectangle-polynomial-modular` and `domicule-cylinder-torus-polynomial-modular` run their first seven cases and the boards of their BigInt twins. `any-lattice-cylinder-torus-pfaffian` runs every board of its file: the largest, of 1600 cells, take about 8 s each in Python and less in Rust and JavaScript.

The commands below run in CI after each merge to master, and on a pull request that changes a file their job reads. The exception is `pnpm -C js test:render`. It is part of `pnpm -C js test` and runs alone only on macOS.

Each CI job runs on its own runner. `Changes` decides which jobs run and whether the b-file generators run, and the other jobs wait for it. `Rust` runs `cargo test` and `cargo clippy --workspace --all-targets -- -D warnings`. `Repository` runs `test:spec`, `test:oeis`, `test:markdown`, `test:numbers`, `test:metadata`, `test:ci` and `test:pari`.

On a pull request a job skips when the pull request changes none of the files it reads. The step "Select the jobs" of `Changes` lists these files as one pattern per job. `Repository` always runs. Every job runs when a pull request changes `ci.yml`, `spec/` or a toolchain file, or deletes or moves a file. The README files of `benchmarks/`, `js/`, `python/` and `rust/` start no job, since only `Repository` reads them. Every job also runs on master, in the weekly run and in a run started by hand. A file missing from a pattern only delays a failure to the run on master after the merge. `test:ci` checks that the pattern of each job matches every JavaScript file the job loads, but not the data files it reads.

`Site tests 1 of 2` and `2 of 2` share out the browser cases of the site that `Site build` built. The other site tests run in shard 1. The required check is `Check`. It passes only when every other job succeeded or was skipped by `Changes`. A failed or cancelled job fails it, and so does a job skipped for any other reason.

pytest runs on four workers (`-n 4`), apart from the tests marked `timing`. These compare a reported time with the wall time of the process. They run alone, after the others. That way no other worker loads the runner while they measure.

Pull requests and master differ here. A newer run of a pull request cancels the older one, while a run on master is never cancelled once it has started. The weekly run and a run started by hand on master wait in the same queue as the runs after a merge. Of the runs waiting there, GitHub keeps only the newest, whose commit holds the merges of the others.

`pnpm -C js test:benchmarks` needs the Rust binaries of `cargo build --release` and the Python package. To pick tests, use `--test-name-pattern` in `node --test` and `-k` in pytest. `cargo test` is coarser. Its filter picks a whole group of the Rust tests.

[REGRESSIONS.md](REGRESSIONS.md) lists every defect fixed so far, the check that fails if it comes back, and how that was shown.

`FULL_CASES=1` runs every known term but the copied counts in any of the three languages. It also runs each [generator](../docs/glossary.md) over its whole b-file. It takes hours in JavaScript and Python and runs outside CI: the 16 × 16 torus alone takes about 75 minutes, `b401988.py` 8 minutes. `GENERATOR_CHECKS=skip` skips the generator runs. CI sets it for a pull request that changes nothing the generators depend on ([`oeis/README.md`](../oeis/README.md)).

The CI job `Research` runs the Python checks of [`research/king-entropy`](../research/king-entropy/README.md): `src/test_paths.py`, `src/test_timed.py`, `src/test_regressions.py`, reruns of `src/derived.py`, `src/errbar.py`, `src/hidden_oos.py`, `src/lspec.py` and `src/ltest.py` against their files in `out/` and of `replication/analyze_eig.py` and `replication/compare_eig.py` against theirs in `replication/out/`, and the syntax of `.zenodo.json`.

The CI job `macOS` runs `js/test/render.test.js`, `src/test_timed.py` and the rerun of `src/lspec.py` again on macOS, where a pipe takes output asynchronously, `ru_maxrss` is in bytes and LAPACK is another build.
