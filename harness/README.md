# Tests

Every command below runs in CI on each pull request, in the order listed, except the full solver run. Before `pnpm test`, CI builds the Rust workspace with `cargo build --release`, runs `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings`, and installs the Python package with `pip install -e python`. `pnpm test` runs `cargo build --release` itself before the tests; a Rust binary that is missing or older than a `.rs` file it is built from, or a Python package that was not installed, fails it.

| command | runner | what it checks |
| --- | --- | --- |
| `pnpm test` | [`testRunner.js`](testRunner.js) | every implementation of every algorithm against the first cases of the files in [`spec/cases/`](../spec/cases/README.md) (`-m 7`), and every implementation of an algorithm kept in more than one language against every case of `periodicTilingTests.json`, `domiculeTilingTests.json` and `dominoTilingTests-BigInt.json` (the larger boards of `periodicTilingTests-Modular.json` stay at `-m 7`, since its 14 × 14 and 16 × 16 tori take minutes in every language, and `domino-tiling-bigint` stops at 16 × 16 under `-m`, since 20 × 20 takes about five minutes in JavaScript and in Python), the Number counts against the BigInt ones and a(0) = 1 of every square, the command-line parsers, the rejection of invalid boards (through every implementation of the algorithms that have more than one), one count from every implementation of `domicule-tiling-modular` on nine small boards, among them a zero side and a single column, the peak memory of every implementation of `periodic-tiling-modular` on a 2 × 18 cylinder (at most 256 MB), the command the executor builds for each language and its refusal of a Rust binary that is missing or older than a `.rs` file it is built from, the Python solvers when the number of processors is unknown, the Python domicule solver through a scratch array of one count, [`spec/algorithms.json`](../spec/algorithms.json) against the solver directories and `spec/cases/` ([`portCheck.js`](portCheck.js): every registered implementation exists in its language's directory, every file there is registered, every language can be run, every file in `spec/cases/` is loaded by `js/core/cases.js` and names known algorithms, every algorithm is checked, has its JavaScript solver [REGRESSIONS.md](REGRESSIONS.md) lists every defect fixed so far, the check that fails if it comes back, and how that was shown.

`node harness/testRunner.js` without `-m` runs every known term through every solver. It takes hours, the 16 × 16 torus alone about 75 minutes, and runs outside CI.

The CI job `Research` runs the Python checks of [`research/king-entropy`](../research/king-entropy/README.md): `src/test_paths.py`, `src/test_timed.py`, `src/test_regressions.py`, reruns of `src/derived.py`, `src/errbar.py`, `src/hidden_oos.py`, `src/lspec.py` and `src/ltest.py` against their files in `out/` and of `replication/analyze_eig.py` and `replication/compare_eig.py` against theirs in `replication/out/`, and the syntax of `.zenodo.json`.

The CI job `macOS` runs `renderTestRunner.js`, `src/test_timed.py` and the rerun of `src/lspec.py` again on macOS, where a pipe takes output asynchronously, `ru_maxrss` is in bytes and LAPACK is another build.
