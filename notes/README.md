# Notes

Each note is Markdown with code cells marked `js run`. `pnpm -C js site:build` runs the cells in order and publishes every note as a page of the [project site](https://dawidrylko.github.io/lattice-dimers/) with the output under each cell, so the results there are recomputed from this repository on every deploy. On GitHub only the code is shown. A cell that throws stops the build, so a cell that checks a result fails the deploy when the result is wrong. Cells write their output with `print`, `table`, `chart`, a line chart drawn as inline SVG in the colours of the page, and `figure(svgs, caption, { highlight })`, a drawing of tilings on a sheet in the colours of the gallery; `drawTilings({ rowCount, colCount, pieces, lattice, surface, diagonals, ranks, spread })` in `site/notes.js` draws them with the gallery's renderer, one SVG per tiling named for screen readers, and `highlight` greys out the straight pieces.

The renderer in `site/notes.js` covers a subset of Markdown: headings, paragraphs, flat lists, tables, block quotes, code blocks, `math` blocks and inline `$...$` (rendered with KaTeX), code spans, links, bold and italics. Nested lists and a `|` inside a table cell are not supported.

The notebooks are grouped as the site menu groups them: the notes of each kind of piece or lattice sit in their own directory, and a note `notes/<group>/<nn>-<name>.md` is published as `notes/<group>/<name>.html`. The notebooks of the groups share one layout, the notebook skeleton of the [glossary](../docs/glossary.md#site): a title with the OEIS entries they count, The problem, one section per solver, Numbering, The counts, their own sections, Running time, PARI/GP, Verification and References; the rectangles notebooks also say how the gallery samples the tilings. A section that took over an older one keeps its old address as a section alias, listed in `SECTION_ALIASES` of `site/chrome.js`.
